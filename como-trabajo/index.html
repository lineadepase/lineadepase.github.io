Método

De la pregunta al resultado

Cada investigación empieza con una pregunta concreta y termina con una página que explica lo que dicen los datos y lo que no. Entre las dos hay siempre los mismos pasos.

  1. Pregunta. Qué se quiere saber, escrito antes de mirar nada.
  2. Datos. Solo fuentes públicas, citadas y con su fecha. Lo que se escribe a mano se guarda en CSV de entrada, con la dirección de la fuente en cada fila.
  3. Revisión de los datos. Se cruzan fuentes y tablas entre sí. Las diferencias y las decisiones que se toman quedan registradas, no se corrigen en silencio.
  4. Método. Un modelo o un cálculo explicado, con sus supuestos. Si hay incertidumbre, se muestra (intervalos, simulaciones, rangos).
  5. Resultado. Cada cifra del texto sale de los datos de salida, no de la memoria.
  6. Límites. Qué no demuestra el análisis y qué datos faltan.
  7. Código. Todo el proceso está en GitHub para que cualquiera lo repita.

Reproducibilidad

Que se pueda repetir

Una investigación solo vale si otra persona puede llegar al mismo resultado. Por eso cada proyecto cumple lo mismo:

  • Un solo script. Un único comando recalcula las tablas, los gráficos y las cifras de la página a partir de los datos de entrada.
  • Versiones fijadas. Un archivo requirements.txt lista las bibliotecas necesarias.
  • Pruebas automáticas. Con ligas o partidos inventados se comprueba que los cálculos hacen lo que dicen. Un proyecto, además, repite sus cálculos en un segundo lenguaje (R) y compara los resultados.
  • Entrada y salida separadas. Lo que se rellena a mano va en datos/entrada; lo que calcula el código, en datos/salida, y no se toca a mano.
  • Revisión visual. Las páginas se miran a 1280 y 390 píxeles de ancho para que nada quede cortado.

Estructura común

Todas las investigaciones se organizan igual

Cada proyecto vive en una carpeta de analisis/ con la misma estructura, así que quien conoce una conoce todas.

analisis/proyecto/
├── README.md
├── requirements.txt
├── codigo/
├── datos/
│   ├── entrada/
│   └── salida/
├── pruebas/
└── documentacion/

README.md recoge la pregunta, el método y cómo repetirlo; codigo/, los scripts; datos/entrada, los datos de partida con su fuente; datos/salida, las tablas calculadas que alimentan la web; pruebas/, las pruebas automáticas, y documentacion/, las decisiones del método.

En la página de cada investigación la estructura es la misma: pregunta, datos, método, resultado, límites y enlace al código.

Base de datos

Una base de datos para todos los proyectos

Los datos de salida de todos los proyectos se reúnen en una única base de datos DuckDB: un solo archivo, sin servidor. Cada proyecto es un esquema y cada CSV de salida es una tabla, con su descripción y su clave documentadas.

  • Se reconstruye entera. No se edita a mano y no se guarda en el repositorio: con los mismos CSV sale siempre el mismo contenido.
  • Catálogo incluido. El esquema meta lista tablas, columnas, tipos, filas y la huella de cada archivo de origen.
  • Vistas entre proyectos. El esquema comun cruza proyectos; por ejemplo, la clasificación del grupo 2 junto a las probabilidades de la simulación.
  • Comprobaciones. Claves únicas, tablas sin huérfanos entre sí y cuadres numéricos (por ejemplo, que cada distribución de puestos sume uno).

Cómo se usa

pip install -r analisis/comun/base_datos/requirements.txt
python analisis/comun/base_datos/cargar.py
python analisis/comun/base_datos/comprobar.py
python -m pytest analisis/comun/base_datos/pruebas

Después se consulta con cualquier cliente de DuckDB. Por ejemplo, la probabilidad de ascenso directo con la clasificación actual:

import duckdb
con = duckdb.connect("analisis/comun/base_datos/salida/linea_de_pase.duckdb", read_only=True)
con.sql("""
  SELECT posicion, equipo, puntos, ascenso_directo
  FROM comun.v_grupo2_actual
  ORDER BY ascenso_directo DESC LIMIT 5
""").show()

El esquema completo, con todas las tablas y columnas, está en ESQUEMA.md.

Límites

Lo que estos análisis no son

Son análisis personales hechos con datos públicos, no información oficial de ningún club ni competición. Los datos de partidos pueden tener errores o diferir entre fuentes; cuando se detectan, se anotan. Si ves algo que no cuadra, escríbeme por el contacto.
